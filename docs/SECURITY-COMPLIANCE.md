# QMoosa / RDL Security and Compliance Baseline

Version 1.0 — Baseline

## Security

The project treats security as an evidence-driven engineering process. Passing tests does not constitute a security guarantee or independent audit.

Controls should include:

- secret and private-key protection
- dependency and vulnerability review
- reproducible builds
- access control and least privilege
- secure node configuration
- monitoring and incident response
- backup and recovery testing
- responsible vulnerability disclosure

## Privacy

Avoid placing unnecessary personal, credential, or confidential information on-chain. Use data minimization and privacy-by-design principles for systems processing personal data.

## Legal and Regulatory

The project must comply with laws and regulations applicable to its actual activities and jurisdictions. This document is not legal advice and does not claim government, court, regulator, or standards-body approval.

For India, the project should assess applicable information-technology, cybersecurity, personal-data, consumer, tax, anti-money-laundering, and virtual-asset requirements according to the actual service model. Other jurisdictions require their own review.

## Claim Policy

No public statement may claim legal compliance, regulatory authorization, security certification, decentralization, or Mainnet status unless the specific claim is supported by appropriate evidence.
