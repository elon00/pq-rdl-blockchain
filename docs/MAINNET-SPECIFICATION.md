# QMoosa / RDL Mainnet Specification

Version 1.0 — Draft

## Purpose

Define production-readiness requirements. This document is a specification, not a claim that Mainnet is currently live.

## Production Requirements

Mainnet promotion requires evidence appropriate to the intended architecture, including:

- deterministic production genesis
- versioned, reproducible release artifacts
- independently administered validators
- persistent ledger and backup/restore procedures
- secure peer-to-peer networking
- verified consensus operation and fault testing
- state synchronization and recovery
- real transaction settlement
- monitoring and incident response
- key-management and access-control procedures
- governance and upgrade procedures
- security review/audit appropriate to the deployment risk
- jurisdiction-specific legal and compliance review where applicable

## Monetary Policy

The current token policy uses an unlimited maximum supply. Mainnet issuance and validator/operator reward parameters must be explicitly implemented, transparently documented, and governed before being represented as final.

## Governance

The final Mainnet governance model may use DAO-based governance, multisignature controls, or other documented mechanisms appropriate to protocol risk. No governance mechanism is considered production-final until implemented and verified.

## Promotion Rule

A Mainnet claim must never be inferred from Testnet success. Mainnet status requires its own production evidence and release decision.
